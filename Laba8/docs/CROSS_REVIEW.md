## 3. Відомі обмеження (варто назвати на захисті, а не чекати питання)

1. `OrderFactory` (CBO 6), `ConsoleApp` (6) і `Main` (17) перевищують ціль ≤ 4 — обґрунтовано в ADR-005.
2. Між кроками післяобробки немає транзакції (ADR-003).
3. `FileOrderRepository.nextId()` читає файл і не потокобезпечний — для однопотокового CLI достатньо.
4. `SimulatedEmailNotifier` лише імітує відправку (адреса зберігається в пам'яті).
5. CBO для legacy-процесора вже дорівнював 4 (п. 3.1 звіту) — покращення видно переважно за структурними індикаторами.

## 4. Підготовка до захисту — типові питання по 9 патернах

| Патерн | Питання | Коротка відповідь (з нашого коду) |
|--------|---------|-----------------------------------|
| Information Expert | Чому `Order.subtotal()`, а не метод сервісу? | `Order` володіє `items`; сервіс довелося б давати доступ до чужих полів → Anemic Model. |
| Creator | Чому `OrderItem.of`, а не `order.addItem(product, qty)`? | Додало б залежність `Order → Product` і підняло CBO до 5 (QOC-002). |
| Controller | Що саме робить `OrderController`? | Фабрика → `process()` → кроки. Без I/O й арифметики, CBO = 4. |
| Low Coupling | Як довели зниження зчеплення? | Таблиця CBO у звіті + `tools/metrics.py`; домен I = 0.00. |
| High Cohesion | Що означає LCOM4 = 1 для `Order`? | Усі методи пов'язані викликами або спільним полем — один компонент. |
| Pure Fabrication | Навіщо `DiscountPolicyRegistry` / парсери, якщо їх нема в домені? | Утримують сутності від інфраструктурних обов'язків. |
| Indirection | Що розриває зв'язок контролер ↔ файл? | Порт `OrderRepository` + `OrderStep`. |
| Polymorphism | Де зник `if-else`? | `Customer.discountOn` → `DiscountPolicy`; вибір — словником у реєстрі. |
| Protected Variations | Що захищає ядро від зміни ПДВ чи формату рахунку? | Інтерфейси `TaxPolicy`, `ReceiptFormatter`; зміна = новий клас у `Main`. |
