# Крос-рев'ю та аргументація (Завдання 5)

## Вибір шаблонів
| Ситуація | Шаблон | Чому |
|---|---|---|
| Завд. 1: нові операції над стабільною структурою типів | **Visitor** | Операції виносяться з класів об'єктів у окремі класи; нова операція = новий Visitor без змін `Runway`, `Terminal`, `JetBridge`, `FuelStorage` (див. `AviationAuthorityReportVisitor`). Double dispatch дає окрему логіку для кожного типу. |
| Завд. 2: зберегти/відновити закритий стан | **Memento** | `Schedule.Snapshot` - вкладений клас з приватним станом: поля розкладу не публічні, `ScheduleHistory` (Caretaker) лише тримає знімки й не бачить вмісту. |
| Завд. 3: різні обходи, невідома структура, паралельні обходи | **Iterator** | Служби працюють лише через `PassengerIterator`; кожен спосіб обходу - окремий клас; кожен ітератор має власний курсор, тому обходи незалежні. |

Чому не навпаки: Visitor не підходить для обходу (він додає операції над типами, а не порядок), Memento не додає операцій, Iterator не зберігає стан.

## Типові питання на захисті
- *Чому `Snapshot` вкладений, а не окремий клас?* Щоб лише `Schedule` мав доступ до приватного стану (вузький інтерфейс Memento).
- *Чому `Flight` - record?* Незмінність: знімок не можна зіпсувати через спільні посилання.
- *Недолік Visitor?* Додавання нового типу об'єкта вимагає змін у всіх Visitor.
- *Чому обходи незалежні?* Курсор (`rowPos`, `index`, `buffered`) зберігається в екземплярі ітератора, а не в `Cabin`.
